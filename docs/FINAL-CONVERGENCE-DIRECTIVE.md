## Product ruling

Underwriting Desk is an integrated financial change-control workspace for private-market underwriting. It complements Excel, a VDR or connected folder, Affinity or DealCloud, and a user's chosen frontier model. It owns controlled analytical state and connects evidence changes to deterministic financial and decision consequences. It is not a CRM, VDR, generic document-chat product, proprietary-data terminal, or source of autonomous investment advice.

## Purchase-defining workflow

`imperfect XLSX + CSV + PDF -> mapped and reconciled evidence -> human-approved Version 1 -> revised Version 2 -> material-change analysis -> deterministic rerun -> stale conclusions and approvals -> named accept/reject/defer -> accepted-state Excel and IC output`

The principal surfaces are:

1. Change Cockpit.
2. Evidence and Work Review.
3. IC Review.

## Authority boundaries

- Source facts remain traceable and versioned.
- Deal terms remain distinct from analyst assumptions.
- Firm policy remains firm-owned.
- Deterministic calculations do not depend on LLM-generated arithmetic.
- Human observations retain author, date, context, visibility, and review state without invented confidence scores.
- Model output begins as a proposal and stays outside the authoritative chain unless a named human promotes it.
- Recommendations, exceptions, approvals, and investment decisions belong to named humans and the IC.

## Final acceptance

A clean desktop browser must prove:

1. XLSX, CSV, and PDF import.
2. Visible mappings, exclusions, ambiguities, and missing information.
3. Human-approved Version 1 baseline.
4. Authored qualitative notes connected to diligence or thesis questions.
5. Revised evidence admitted as Version 2.
6. Material changes and deterministic financial consequences displayed.
7. Every affected assumption, issue, approval, and memo section becomes stale.
8. A named reviewer can accept, reject, or defer.
9. Rejection preserves Version 1.
10. Acceptance alone updates canonical state.
11. Excel output contains only accepted values and version references.
12. The IC memo contains only the accepted scenario and evidence.
13. Sources are traceable in finance-native language and within three interactions.
14. A connected model can read and propose through bounded MCP tools without authoritative mutation.
15. Reload and state restoration succeed.
16. The public-record case enforces its historical cutoff.
17. No broken controls, clipped content, migration warning, obvious grammar error, or default-view machine debris remains.
18. Repository, release, deployment, and exact commit agree.
